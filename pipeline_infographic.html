How a document travels through docIS

From upload to a validated invoice. PDFs, images and spreadsheets share the same intake, AI extraction and checks. They differ in one stage: how the text is pulled out of the file.

PDF.pdf Images.jpg .png .tiff Spreadsheets.xlsx .xls .csv
1

Upload and gatekeeping

POST /documents

Every file

  • Whole request capped before it is parsed. At most 20 files, 50 MB each → 413
  • Extension must be accepted, and the first bytes must match it %PDF-, FF D8 FF, PK… → 415
  • Streamed to storage while a SHA-256 hash is computed (used later to spot duplicates)
  • One bad file rejects the whole batch. Otherwise uploaded and the API answers 201

Content check per type → 422

  • PDF: opens, not password-protected, has pages
  • Image: decodes, and the format matches the extension
  • Sheet: valid workbook, not encrypted, no zip bomb. A CSV must decode and hold data
2

Queued for a background worker

Celery + Redis
  • A processing job is written in the same transaction as the document, and sent to the queue only after commit
  • A worker claims it with a 5-minute lease (a duplicate delivery is skipped). Status processing, with progress you can poll at /documents/{id}/processing
3

Content extraction: one lane per file type

app/processing/

PDF

pypdf · PDFium
  1. Read the text layerEvery page, normalised
  2. Is the page a scan?
    Under 20 visible characters and contains an image → OCR this page. Otherwise keep its text
  3. Render scanned pages300 DPI, capped at 50 megapixels
  4. Clean up, then TesseractSame image clean-up as the image lane
  5. MergeText and OCR pages, back in page order
Digital PDFs never run OCR, so they're fast. A mixed PDF only OCRs its scanned pages.

Images

Pillow · Tesseract
  1. Each frame is a pageA multi-page TIFF gives several pages
  2. NormaliseApply EXIF rotation, transparency onto white, grayscale
  3. Enlarge small imagesUp to a 1,500 px long side, before clean-up
  4. Clean up only what's measured as needed
    Dark or shadowed → remove grain, flatten lighting, stretch contrast, whiten paper. Then straighten up to ±15°
  5. TesseractText plus word confidence. Below 60, also tries the page rotated 90°/180°/270°
Hardest lane: photos 79.8% of fields, handwriting 51.4%. Blur is the weak spot.

Spreadsheets

openpyxl · xlrd
  1. Pick the readerXLSX: openpyxl · XLS: xlrd · CSV: built-in
  2. CSV detection
    Delimiter sniffed from , ; tab |. Encoding UTF-8, falling back to Windows-1252
  3. Every sheet becomes a gridTyped cells (numbers, dates, text). Empty trailing rows and columns are trimmed
  4. Size guardUp to 1 million cells per sheet, then cut at a row and marked truncated
No OCR and no image clean-up. Cell values arrive exactly as stored.
4

Saved and made searchable

PostgreSQL + pgvector
  • Pages are stored with their method (text layer or OCR) and OCR confidence. Sheets are stored as grids
  • The text is split into chunks of about 1,200 characters with 150 characters of overlap, keyword-indexed, and embedded with bge-small for semantic search
  • Status processed. The invoice job is queued next
5

AI invoice extraction

Claude, structured output
  • The document is rendered as text with page and sheet markers. Sheet rows read as cell | cell | cell
  • Long documents are split into parts of 50,000 characters, up to 4 at a time and at most 120 parts. The parts are then merged
  • The reply must match the invoice schema. A value that isn't printed is null, never guessed. Doubtful fields are listed in uncertain_fields
  • Normalised: blanks become null, currency codes are upper-cased, credit-note signs are made consistent

7

Review, correct, search

React UI + REST API
  • Review queue lists every document with open flags
  • Corrections are saved with history, and every check runs again
  • Keyword and semantic search across all files
  • Cross-check documents: PDF against PDF, PDF against Excel
!

When a step fails

any stage after upload
  • Temporary problems (timeouts, database or AI briefly unavailable) are retried with growing delays, up to 3 attempts
  • Permanent problems, or retries used up, set status failed with a plain-language reason. A Retry button runs it again
  • Jobs whose worker died are picked up again automatically once their lease expires
